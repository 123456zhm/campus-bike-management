# 校园业务数据库脚本

- 目标版本：MySQL 8.0.16 及以上，字符集 utf8mb4，InnoDB。
- 仅在新建的专用数据库中初始化：先导入若依的 `sql/ry_20260417.sql` 和 `sql/quartz.sql`，再导入 `001_schema.sql`；演示需要时导入 `002_demo_data.sql`。
- 若依原始初始化脚本包含 DROP TABLE，切勿直接导入已有业务数据的数据库。校园业务建表脚本不包含 DROP，也不会创建或选择数据库。
- 若依示例账号和密码仅供本地演示，使用前应修改；数据库密码通过环境变量配置，不写入仓库。
- `001_schema.sql` 是初始版本，不可重复导入同一数据库；未来结构修改使用新的迁移脚本。
- 执行 `003_account_role.sql` 创建 `campus_user` 角色。校园普通用户应只分配此角色；若依自带的 `common` 示例角色包含管理权限，不能作为校园普通用户角色使用。原有账户和角色关系不会自动更改。
- 一张订单最多一张账单；模拟支付仅支持一次全额支付。零元订单创建已支付零元账单，不生成支付流水。
- 借车时锁定用户和车辆，校验欠费及权限后在同一事务中更新车辆并创建订单。唯一索引为并发提供第二道防线。还车、创建账单和车辆状态更新需要事务；表约束不能代替服务端权限与业务校验。
- 收费规则只新增版本，借车时复制计时单位和单价到订单；修改收费规则须在事务中停用旧规则、启用新规则。
- 当前先验证了建表、唯一索引、外键、金额约束、订单状态约束和并发争抢同一车辆；完整业务流还需在应用实现后联调。
